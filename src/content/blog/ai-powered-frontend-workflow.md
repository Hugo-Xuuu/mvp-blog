# AI 赋能前端工作流：我用自动化工具重构个人博客的全记录

## 背景

"白日梦的博客"最初是一个粗糙的 MVP——单个 `index.astro` 文件里堆了全部代码，没有组件化、没有内容管理、没有 SEO、没有 RSS。

在最近一次全量重构中，我尝试了 **AI 辅助开发**的模式：让 AI 担任架构师 + 初级工程师，我担任审查者 + 决策者。

这篇文章记录这个过程。

## AI 参与的角色

### 角色 1：架构分析师

AI 首先读取了整个项目结构，给出了详细的诊断报告：

```
诊断结果：
├── ❌ 单页巨石 — 全部代码在 index.astro
├── ❌ 内容管理原始 — 使用 import.meta.glob
├── ❌ 样式策略混乱 — CDN + Vite 插件双加载
├── ❌ 无布局系统 — 没有 Layout 组件
└── ❌ 缺失功能 — SEO/RSS/分页/标签/搜索
```

这个分析帮我快速看清了问题全貌。

### 角色 2：代码生成器

AI 根据架构规划生成了大部分代码，我的主要工作是：

1. 将 `[...slug].astro` 改为 `[slug].astro`（Astro v7 路由规则变更）
2. 将 `post.render()` 改为 `render(post)`（Loader API 变更）
3. 将所有 `post.slug` 改为 `post.id.replace('.md', '')`
4. 添加 `encodeURIComponent` 处理中文标签

这些修复只花了约 **10 分钟**。如果手写全部代码，至少需要 **2-3 天**。

## 工作流对比

### 传统方式

```
需求分析 → 手写架构文档 → 逐文件编码 → 手动测试 → Debug → 重复
```

### AI 辅助方式

```
需求描述 → AI 架构规划 → 审查并确认 → AI 生成代码 → 修复边界情况 → 完成
```

关键差异：**从"写代码"转变为"审查代码"**。

## 实践中的经验教训

### 教训 1：AI 生成的代码需要"边界审查"

AI 能生成 90% 正确的代码，但边界情况需要人工审查：

- **路由冲突**：`[...slug]` catch-all 路由会覆盖 `/blog` 静态路由 → 改为 `[slug]`
- **API 版本差异**：Astro v7 的 Loader API 使用 `glob()` 而非旧版 `defineCollection()` → 查阅文档修正
- **编码问题**：中文标签在 URL 中需要编码 → 添加 `encodeURIComponent`

### 教训 2：精确的需求描述 > 模糊的对话

对比这两种提示词：

```markdown
❌ "帮我做个博客"
✅ "在 Astro v7 + Tailwind v4 项目中，创建 Content Collections 配置，
使用 glob loader 加载 src/content/blog 下的 .md 文件，
Zod schema 包含 title、date、tags、description、draft 字段"
```

描述越精确，结果越可用。

### 教训 3：工具链是杠杆

AI 不是独立工作的，需要配合正确的工具链：

| 工具                    | 用途                     |
| ----------------------- | ------------------------ |
| **Astro**               | 框架 — 提供 Islands 架构 |
| **Tailwind v4**         | 样式 — 原子化 CSS        |
| **Content Collections** | 内容管理 — 类型安全      |
| **pnpm**                | 包管理 — 快速可靠        |
| **AI 辅助工具**         | 代码生成 — 加速开发      |

## 给前端开发者的建议

1. **把 AI 当结对编程伙伴**，而非替代品。它擅长生成，你擅长决策。
2. **不要直接信任输出**。AI 不知道你用的框架版本号的细节差异，每次生成后都要检查。
3. **利用 AI 做架构设计**。描述你的需求，让 AI 生成几个方案，你评估优劣。
4. **保留核心决策权**。技术选型、架构风格、命名规范这些应该由人决定。

## 效果总结

这次重构在约 **2 小时内** 完成了：

| 维度     | 重构前 | 重构后        |
| -------- | ------ | ------------- |
| 组件数   | 0      | 16            |
| 页面数   | 1      | 11            |
| 构建时间 | 未测量 | ~700ms        |
| 构建错误 | 未知   | 0             |
| SEO      | 无     | OGP + JSON-LD |
| RSS      | 无     | RSS 2.0       |

这并不意味着 AI 可以替代前端工程师。**工具越强，对使用工具的人的要求就越高。**
